# codex-kit

Codex CLI로 몇 시간짜리 업무 과제를 풀 때 쓰는 작업 규칙과 스킬 모음이다. 과제 답, 개인정보, 키는 들어 있지 않다.

## 사용법

작업 폴더에서 사람이 직접 실행한다.

```bash
git clone https://github.com/hyeongus2/codex-kit /tmp/kit
bash /tmp/kit/setup.sh
```

그다음 Codex를 다시 켜고(`/quit` → `codex`) 두 가지를 확인한다.

1. `/skills`에 스킬 4개가 보이는지
2. "커밋하면 안 되는 파일과 이유, 단계를 시작하기 직전에 할 일, 검증할 때 확인할 네 가지를 말해"라고 물었을 때 규칙대로 답하는지 (설치된 것과 적용된 것은 다르다)

설치 출력에 [주의]가 있으면 그 줄을 복사해 Codex 첫 메시지에 붙여 넣는다. Codex는 설치 출력을 보지 못한다.

Codex 샌드박스가 `.git`을 읽기 전용으로 막으면 `git add`·`git commit` 때 승인 창이 뜬다. 승인 창에서는 `Yes, proceed`(이번만)를 고른다. `don't ask again for commands that start with ...`는 `~/.codex/rules`에 규칙을 저장하므로 고르지 않는다.

Codex에게 설치를 시켜도 되지만, 네트워크 접근과 `~/.agents` 쓰기 때문에 승인 창이 뜬다. 사람이 직접 치는 쪽이 빠르고, 설치 작업이 과제 기록에 섞이지 않는다.

설치가 계속 막히면 오래 붙잡지 말고 키트 없이 진행한다. 짧은 AGENTS.md를 작업 폴더에 직접 쓰면 된다.

## setup.sh가 하는 일

| 순서 | 대상 | 동작 |
|---|---|---|
| 1 | `./AGENTS.md` | 없으면 복사. 있으면 기존 내용은 두고 맨 뒤에 키트 규칙을 한 번만 덧붙임. `AGENTS.override.md`가 있으면(빈 파일 포함) 키트 규칙이 적용되지 않는다고 경고. 32,768바이트를 넘어 Codex가 뒷부분을 잘라 읽게 되면 경고 |
| 2 | `./PLAN.md`, `./INTERVIEW.md`, `./DECISIONS.md` | 없을 때만 복사. 키트 양식과 다른 파일이 이미 있으면 덮어쓰지 않고 경고. 이름은 달라도 계획·결정·메모 역할일 수 있는 문서(`TODO.md`, `TASKS.md`, `docs/plan.md` 등, 세 단계 깊이까지)가 있으면 목록을 알려 줌 |
| 3 | `./.gitignore` | 없으면 복사. 있으면 빠진 줄만 맨 앞에 넣어 기존 규칙(예외 포함)이 우선하게 함. 과제 규칙이 PLAN.md·INTERVIEW.md·DECISIONS.md를 무시하면 경고 |
| 4 | `~/.agents/skills/` | 스킬 4개 복사. 같은 이름이 있으면 덮어쓰지 않고, 내용이 같은지 다른지 알려 줌. 작업 폴더부터 저장소 맨 위까지의 `.agents/skills`·`.codex/skills`와 `~/.codex/skills`에 같은 이름 스킬이 있으면 `$이름` 호출이 무시된다고 경고. 실패해도 1~3은 남음 |

인터넷 접속, sudo, `~/.codex` 수정, 파일 삭제는 하지 않는다. 기존 파일은 덮어쓰지 않고, 기존 AGENTS.md 뒤와 .gitignore 앞에 덧붙이기만 한다. 여러 번 실행해도 결과가 같다. 종료 코드는 0(완료), 1(작업 폴더 파일 설치 실패), 2(완료, 주의 사항 있음)이다.

## 파일

| 경로 | 역할 |
|---|---|
| `AGENTS.md` | Codex가 켜질 때 자동으로 읽는 고정 규칙. 과제 내용은 넣지 않는다 |
| `templates/PLAN.md` | 시작 상태, 목표와 범위, 요구사항(R번호, 근거, 완료 조건), 데이터, 단계별 계획(구현 내용, 완료 조건, 검증, 결과), 예상 밖 발견, 다음 할 일, 결과와 한계 |
| `templates/INTERVIEW.md` | 담당자 문답 원문(Q번호), 반영한 곳, 물어볼 질문, 답을 못 받은 것 |
| `templates/DECISIONS.md` | 결정마다 결정, 이유, 버린 대안, 근거, 영향 |
| `templates/gitignore` | 가상환경, 패키지 폴더, `.env`, 캐시가 커밋되지 않게 막는 목록 |
| `skills/*/SKILL.md` | 필요할 때 부르는 작업 절차 4개 |
| `setup.sh` | 위 파일들을 제자리에 놓는 설치 스크립트 |
| `.gitattributes` | 줄바꿈을 LF로 고정해 리눅스에서 `setup.sh`가 깨지지 않게 함 |

## 스킬

`$이름`으로 부르면 Codex가 그 SKILL.md 내용 전체를 그 메시지에 붙여 보낸다(그 메시지에만 적용). 이름만 말하거나 요청이 설명과 분명히 맞거나 AGENTS.md 규칙이 가리키면 Codex가 스스로 SKILL.md를 열어 쓰기도 한다. 썼는지는 Codex가 "○○ 스킬로"라고 말하는지, Ctrl+T 기록에 그 SKILL.md를 읽은 줄이 있는지로 확인한다. 꼭 써야 하면 `$이름`으로 부른다. 같은 이름 스킬이 두 곳에 있으면 직접 친 `$이름`은 무시되므로 "SKILL.md 경로 읽고 그 절차대로 해"라고 한다.

| 스킬 | 부르는 때 | 하는 일 |
|---|---|---|
| `interview-questions` | README를 읽은 뒤, 데이터를 본 뒤, 담당자 답을 붙여 넣을 때 | 문답을 INTERVIEW.md에 원문 기록, PLAN.md 요구사항·단계 계획 반영, 다음 질문을 우선순위대로 추가, 합의 확인 메시지 |
| `data-profile` | 데이터를 처음 다룰 때 | 형식 확인, 열별 빈 값·중복·이상값·표기 차이를 숫자로, PLAN.md '데이터'에 기록, 처리 전후 비교 |
| `verify-before-done` | 과제 구현 단계를 끝낼 때 | 정상·예외·경계·잘못된 입력 경우 실제 실행(기대값은 코드와 다른 방법으로), 테스트 파일로 남기고 앞 단계 테스트도 재실행, 범위 점검, 기록 갱신, 스테이징 내용 보안 점검, 파일 지정 커밋 |
| `final-check` | 제출 준비를 시작할 때 | 제출물 대조(.gitignore에 걸린 제출물 확인 포함), 전체 테스트, 요구사항별 충족 여부, 결과와 한계, 시작 상태와 비교한 커밋 점검, 제출 후 질문 대비 요약 |

## AGENTS.md 규칙의 근거

`공식` = 응시 환경 공식 안내, `관찰` = 사전 체험 후기, `판단` = 작성자 판단.

| 규칙 | 근거 |
|---|---|
| README > 담당자 답 > 이 파일 | 공식: 과제 목표·필수 조건·제출물은 README 기준 |
| 요구사항에 없는 기능 금지 | 평가 도구 개발팀 인터뷰: 과잉 설계는 중점 감점 대상 |
| 실행 출력으로 검증, 실패하면 같은 검증으로 재확인 | 평가 도구 공개 자료의 충족 신호 |
| PLAN.md·INTERVIEW.md·DECISIONS.md를 길이 제한 없이 자세히 기록 | 판단. 평가 도구 데모 과제의 제출물에 DECISIONS.md가 있음 |
| 담당자 문답은 원문 그대로 INTERVIEW.md에 | 판단: Codex는 메신저를 못 보고, 대화가 자동 요약되면 붙여 넣은 원문이 사라질 수 있음 |
| 단계 시작 직전에 그 단계 계획을 다시 검토 | 판단: 앞 단계 결과와 새 담당자 답이 계획을 바꿀 수 있음 |
| 정상·예외·경계·잘못된 입력을 각각 검증하고 테스트로 남김 | 판단: 최종 점검에서 같은 검증을 다시 돌리기 위해 |
| 기대값은 구현 코드가 아닌 방법으로 정하고, 누가 계산했는지 적음 | 판단: 코드 출력을 기대값으로 쓰면 코드가 틀린 그대로 테스트가 통과함. AI 계산을 사람이 했다고 기록하면 후속 서술형에서 설명할 수 없음 |
| 기록 파일은 커밋, AGENTS.md·.gitignore·`.agents/`는 커밋 안 함 | 판단: 시험장은 홈 폴더가 저장소라 키트 파일이 미추적으로 보임. 커밋에는 과제 결과와 기록만 남김 |
| 시작 상태를 키트 파일·환경 파일·과제가 준 파일로 나누고, 고친 과제 파일은 커밋 | 판단: 과제 소스가 미추적이면 '처음부터 있던 파일'로 묶여 핵심 수정이 커밋에서 빠질 수 있음(독립 검토 실행 확인) |
| `.git`이 막히면 승인 요청으로 재실행, 우회 금지 | Codex 0.163 소스: 작업 공간 쓰기 모드는 `.git`·`.agents`·`.codex`를 읽기 전용으로 둠. 독립 검토에서 키트 없는 Codex는 임시 저장소·bundle로 우회함 |
| `git commit -a`, `git add -f` 금지 | 판단: 키트가 덧붙인 과제 파일 변경이 섞이거나 과제 .gitignore를 뚫음 |
| 내가 띄우지 않은 프로세스 종료 금지, 플랫폼 설정·연결 프로세스 수정 금지 | 공식: 플랫폼 관리 설정이나 연결 프로세스를 수정·종료하지 말 것 |
| 외부 코드는 일부만, 출처 기록 | 공식: 외부 코드 일부 차용은 가능, 결과물 통째 대체 불가, 사용 자료는 검토 대상 |
| 큰 출력·반복 읽기 줄이기 | 공식: AI 사용량과 활용 과정은 평가에 참고될 수 있음 |
| 과제가 준 계획·결정 파일과 형식을 우선, '기록 위치'에 대응 기록 | 공식: README가 정한 파일 이름·형식이 우선. 대응 방식은 판단 |
| 같은 이름 스킬 경고 | Codex 0.163 소스: 같은 이름 스킬이 둘이면 직접 친 `$이름`은 선택되지 않음 |
| 준비 작업은 기록·커밋하지 않음 | 판단: 설치 작업이 과제 기록에 섞이는 것을 연습 중 확인 |
| 시작 git 상태를 적고 환경 파일은 건드리지 않음 | 관찰: 작업 폴더가 홈 폴더이고 환경 파일이 미추적으로 보일 수 있음 |
| 시각은 한국 시간으로 계산 | 판단: 서버 시간대가 한국 시간이 아닐 수 있음 |
| push 금지 | 공식 |
| 커밋할 파일을 하나씩 지정하고 스테이징 내용을 확인 | 판단: `git diff`만으로는 새 파일과 스테이징한 파일이 보이지 않음 |
| `python3` 사용 | 관찰: `python` 명령이 없었음 |
| 서버 0.0.0.0 바인딩 | 공식 |
| 1024 이상 포트 | 관찰: 1024 미만 포트는 거부됨 |
| 서버를 백그라운드로 실행 | 판단: Codex가 서버를 켜 둔 채 다음 작업을 이어 감 |
| Vite `allowedHosts` | 공개 키트 메모와 Vite 자체 보안 동작 |
| 설치가 막히면 표준 라이브러리 | 판단 |
| 개인 API 키 금지, 키·토큰 공개 금지 | 공식 |
| 키·토큰은 환경변수로 | 평가 도구 사이트의 채점 기준 문구 (구버전일 수 있음) |
| 화면 자동 조작, 설정 우회 금지 | 공식 |
