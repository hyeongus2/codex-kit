# codex-kit

Codex CLI로 몇 시간짜리 업무 과제를 풀 때 쓰는 작업 규칙과 스킬 모음이다. Codex 세션 여러 개와 각 세션의 하위 에이전트가 같은 작업 폴더에서 동시에 나눠 일하도록 짜여 있다. 과제 답, 개인정보, 키는 들어 있지 않다.

## 사용법

과제 README.md가 있는 작업 폴더(예: `~/workspace`)에서 사람이 직접 실행한다. 먼저 `ls`로 README.md가 보이는지 확인한다.

```bash
git clone https://github.com/hyeongus2/codex-kit /tmp/kit
bash /tmp/kit/setup.sh
```

그다음 Codex를 다시 켜고(`/quit` → `codex`) 두 가지를 확인한다.

1. `/skills`에 스킬 6개가 보이는지
2. "역할별로 고칠 수 있는 파일, 커밋하는 명령의 형태, 쓰면 안 되는 git 명령, 검증할 때 확인할 네 가지를 말해"라고 물었을 때 규칙대로 답하는지 (설치된 것과 적용된 것은 다르다)

## 세션 띄우기

세션마다 터미널 하나다. 응시 환경에서 새 터미널을 열고(`+`) 작업 폴더에서 `codex`를 켠 뒤 첫 메시지로 역할을 준다.

| 순서 | 세션 | 첫 메시지 | 언제 |
|---|---|---|---|
| 1 | lead | `역할: lead. README 읽고 시작해` | 설치 직후 |
| 2 | ask | `역할: ask. README 읽고 담당자 질문부터 모아` | lead와 같이 바로 |
| 3 | part-<이름> | `역할: part-<이름>. README와 CONTRACT.md 읽고 시작해` | lead가 세션 표와 뼈대를 커밋한 뒤. 이름과 수는 PLAN.md '세션 표'를 따른다 |
| 4 | check | `역할: check. README와 CONTRACT.md 읽고 시작해` | CONTRACT.md가 나온 뒤 |

- lead가 split-parts 스킬로 세션 수와 이름, 각 세션의 첫 메시지를 PLAN.md '세션 표'에 적고 보여 준다. 그대로 붙여 넣으면 된다.
- AGENTS.md는 Codex가 켜질 때 스스로 읽으므로 첫 메시지에 넣지 않아도 된다. 설치 [주의]가 AGENTS.md를 못 읽는다고 했거나, 세션을 켠 뒤 AGENTS.md가 바뀌었으면 "AGENTS.md 읽고 따라"를 덧붙인다. README는 스스로 읽지 않으므로 첫 메시지에 넣는다.
- 세션끼리는 파일로 맞춘다. 각자 `work/<역할>.md` 맨 위 '상태'와 '요청'을 쓰고, 단계마다 남의 상태·요청과 CONTRACT.md '변경 이력'을 읽는다. 기다리던 것이 끝났으면 사람 확인 없이 다음 단계로 간다.
- 담당자 질문은 각 세션이 자기 work 파일 '질문'에 쓰고, ask가 모아 중복을 빼고 INTERVIEW.md '다음에 보낼 질문 묶음'으로 만든다. 사람은 그 묶음을 담당자에게 보내고 답을 ask 터미널에 붙여 넣는다.
- 각 세션은 오래 걸리고 서로 독립인 일을 하위 에이전트에게 나눠 동시에 돌린다.
- 세션이 기다리는 중이면 무엇을 기다리는지와 끝나면 뭐라고 말하면 되는지를 알려 준다. 그 말을 그 터미널에 넣으면 이어 간다.

설치 출력에 [주의]가 있으면 그 줄을 복사해 Codex 첫 메시지에 붙여 넣는다. Codex는 설치 출력을 보지 못한다. 터미널에서는 텍스트를 선택한 뒤 `Ctrl+C`로 복사하고 `Ctrl+Shift+V`로 붙여 넣는다. 선택 없이 누른 `Ctrl+C`는 실행 중인 명령(Codex 포함)을 멈추므로 조심한다.

Codex 샌드박스가 `.git`을 읽기 전용으로 막으면 `git add`·`git commit` 때 승인 창이 뜬다. 공식 안내대로 확인 후 한 번 승인한다: `Yes, proceed`(이번만)를 고른다. `don't ask again for commands that start with ...`는 `~/.codex/rules`에 규칙을 저장하므로 고르지 않는다.

스킬은 Codex 표준 위치(`~/.agents/skills`)에 복사한다. 응시 환경이 스킬 적용 방법을 따로 안내하면 그 방법을 따르고, 모르면 Cofa Helper에게 묻는다. 스킬을 쓸 수 없으면 Codex에게 "`/tmp/kit/skills/<이름>/SKILL.md` 읽고 그 절차대로 해"라고 한다.

키트는 MCP를 쓰지 않는다. MCP는 응시 환경의 MCP 탭에서 과제에 필요할 때만 설정할 수 있다.

에디터에 PLAN.md 같은 기록 파일을 열어 둔 채 Codex가 그 파일을 고치면 "외부 변경 감지"가 뜬다. 이때는 "외부 변경 불러오기"를 골라 Codex가 쓴 최신 내용을 가져온다.

Codex에게 설치를 시켜도 되지만, 네트워크 접근과 `~/.agents` 쓰기 때문에 승인 창이 뜬다. 사람이 직접 치는 쪽이 빠르고, 설치 작업이 과제 기록에 섞이지 않는다.

설치가 계속 막히면 오래 붙잡지 말고 키트 없이 진행한다. 짧은 AGENTS.md를 작업 폴더에 직접 쓰면 된다.

## setup.sh가 하는 일

| 순서 | 대상 | 동작 |
|---|---|---|
| 0 | 작업 폴더 | README가 없으면 작업 폴더를 잘못 골랐을 수 있다고 경고 |
| 1 | `./AGENTS.md` | 없으면 복사. 있으면 기존 내용은 두고 맨 뒤에 키트 규칙을 한 번만 덧붙임. `AGENTS.override.md`가 있으면(빈 파일 포함) 키트 규칙이 적용되지 않는다고 경고. 32,768바이트를 넘어 Codex가 뒷부분을 잘라 읽게 되면 경고 |
| 2 | `./PLAN.md`, `./INTERVIEW.md`, `./DECISIONS.md`, `./CONTRACT.md`, `./work/_template.md` | 없을 때만 복사. 키트 양식과 다른 파일이 이미 있으면 덮어쓰지 않고 경고. 이름은 달라도 계획·결정·메모·약속 역할일 수 있는 문서(`TODO.md`, `TASKS.md`, `docs/plan.md` 등, 세 단계 깊이까지)가 있으면 목록을 알려 줌 |
| 3 | `./.gitignore` | 없으면 복사. 있으면 빠진 줄만 맨 앞에 넣어 기존 규칙(예외 포함)이 우선하게 함. 과제 규칙이 기록 파일(PLAN.md·INTERVIEW.md·DECISIONS.md·CONTRACT.md·work/)을 무시하면 경고 |
| 4 | `~/.agents/skills/` | 스킬 6개 복사. 같은 이름이 있으면 덮어쓰지 않고, 내용이 같은지 다른지 알려 줌. 작업 폴더부터 저장소 맨 위까지의 `.agents/skills`·`.codex/skills`와 `~/.codex/skills`에 같은 이름 스킬이 있으면 `$이름` 호출이 무시된다고 경고. 실패해도 1~3은 남음 |

인터넷 접속, sudo, `~/.codex` 수정, 파일 삭제는 하지 않는다. 기존 파일은 덮어쓰지 않고, 기존 AGENTS.md 뒤와 .gitignore 앞에 덧붙이기만 한다. 여러 번 실행해도 결과가 같다. 종료 코드는 0(완료), 1(작업 폴더 파일 설치 실패), 2(완료, 주의 사항 있음)이다.

## 파일

| 경로 | 역할 |
|---|---|
| `AGENTS.md` | Codex가 켜질 때 자동으로 읽는 고정 규칙. 모든 세션이 같이 읽고, 역할별로 할 일과 고칠 파일이 나뉜다. 과제 내용은 넣지 않는다 |
| `templates/PLAN.md` | lead만 씀. 시작 상태, 환경(메모리·CPU), 시간표, 목표와 범위, 요구사항(R번호, 근거, 완료 조건, 맡은 세션), 데이터, 세션 표, 부품 나누기, 전체 진행표, 통합 단계, 예상 밖 발견, 다음 할 일, 결과와 한계 |
| `templates/CONTRACT.md` | lead만 씀. 세션끼리 맞출 약속: 변경 이력, 파일 주인, 공용 파일, 데이터 형식과 인터페이스(실제 예시 값), 실행·테스트 명령, 포트, 설치한 패키지 |
| `templates/work.md` | `work/_template.md`로 설치. 세션마다 복사해 `work/<역할>.md`로 씀: 상태, 맡은 범위, 요청, 받은 요청 처리, 질문, 단계 계획과 결과, 하위 에이전트에게 맡긴 일, 다음 할 일 |
| `templates/INTERVIEW.md` | ask만 씀. 담당자 문답 원문(Q번호), 확정된 사실(F번호), 영역별 확인 현황, 다음에 보낼 질문 묶음, 물어볼 질문, 답 배포, 답을 못 받은 것 |
| `templates/DECISIONS.md` | 모든 세션이 끝에 덧붙임(D-역할-번호). 결정마다 결정, 정한 사람(사람/AI), 이유, 버린 대안, 근거, 영향 |
| `templates/gitignore` | 가상환경, 패키지 폴더, `.env`, 캐시가 커밋되지 않게 막는 목록 |
| `skills/*/SKILL.md` | 필요할 때 부르는 작업 절차 6개 |
| `setup.sh` | 위 파일들을 제자리에 놓는 설치 스크립트 |
| `.gitattributes` | 줄바꿈을 LF로 고정해 리눅스에서 `setup.sh`가 깨지지 않게 함 |

## 스킬

`$이름`으로 부르면 Codex가 그 SKILL.md 내용 전체를 그 메시지에 붙여 보낸다(그 메시지에만 적용). 이름만 말하거나 요청이 설명과 분명히 맞거나 AGENTS.md 규칙이 가리키면 Codex가 스스로 SKILL.md를 열어 쓰기도 한다. 썼는지는 Codex가 "○○ 스킬로"라고 말하는지, Ctrl+T 기록에 그 SKILL.md를 읽은 줄이 있는지로 확인한다. 꼭 써야 하면 `$이름`으로 부른다. 같은 이름 스킬이 두 곳에 있으면 직접 친 `$이름`은 무시되므로 "SKILL.md 경로 읽고 그 절차대로 해"라고 한다.

| 스킬 | 부르는 때 | 하는 일 |
|---|---|---|
| `split-parts` | lead가 요구사항을 정한 뒤 | 파일이 겹치지 않게 부품 나누기, 세션 수와 이름, CONTRACT.md 작성, 뼈대 커밋, PLAN.md 세션 표(각 세션 첫 메시지 포함)·시간표 |
| `integrate` | lead가 부품이 끝날 때마다, 첫 통합과 기능 동결 때 | 모든 work 파일 확인, 전체 실행·통합 테스트, 깨진 곳을 주인 세션에 요청, 통합 서버, 전체 진행표 갱신, 동결 알림 |
| `interview-questions` | ask(없으면 lead)가 README를 읽은 뒤, 담당자 답을 붙여 넣을 때, 정리를 마칠 때마다 | 모든 work 파일에서 질문과 이상한 점 모으기, 중복 빼기, 질문 묶음, 문답 원문 기록, 확정된 사실, 답 배포, 합의 확인 메시지 |
| `data-profile` | 데이터를 처음 다룰 때 | 형식 확인, 열별 빈 값·중복·이상값·표기 차이를 숫자로, PLAN.md '데이터'(lead가 아니면 자기 work 파일)에 기록, 처리 전후 비교 |
| `verify-before-done` | 과제 구현 단계를 끝낼 때 | 정상·예외·경계·잘못된 입력 경우 실제 실행(기대값은 코드와 다른 방법으로), 인터페이스 예시 값 확인, 테스트 파일로 남기고 앞 단계 테스트도 재실행, 범위 점검, 기록·상태 갱신, 보안 점검, 자기 파일만 지정해 커밋, 다음 단계 이어서 시작 |
| `final-check` | lead가 제출 준비를 시작할 때 | 모든 세션 마무리·커밋 확인, 제출물 대조(.gitignore에 걸린 제출물 확인 포함), 전체 테스트, 요구사항별 충족 여부, 결과와 한계, 시작 상태와 비교한 커밋 점검, 제출 후 질문 대비 요약 |

## AGENTS.md 규칙의 근거

`공식` = 응시 환경 공식 안내, `관찰` = 사전 체험 후기, `판단` = 작성자 판단.

| 규칙 | 근거 |
|---|---|
| README > 담당자 답 > 이 파일 | 공식: 과제 목표·필수 조건·제출물은 README 기준 |
| 세션 여러 개와 하위 에이전트로 동시에 나눠 일함 | 공식: 에이전트의 응답 시간을 고려한 위임과 시간 안배도 AI 활용 역량에 포함. 응시 환경은 터미널을 더 열 수 있음. 평가 도구 개발팀 인터뷰: 오래 걸리는 구현을 하위 에이전트에 맡기는 것을 높게 봄 |
| 파일 하나에 주인 세션 하나, 공용 파일·PLAN·CONTRACT는 lead만 | 판단: 같은 파일을 여러 세션이 동시에 고치면 서로 덮어씀 |
| 세션끼리는 work 파일 '상태'·'요청'과 CONTRACT '변경 이력'으로 맞춤 | 판단: 세션은 서로의 대화를 보지 못하고, 대화는 자동 요약되면 사라짐. 파일만 남음 |
| 커밋은 `git commit -- 파일들`로 자기 파일만 | git 동작: 스테이징 목록은 저장소에 하나라 파일 없이 커밋하면 다른 세션이 올려 둔 파일이 같이 들어감. 파일을 지정하면 그 파일만 들어가는 것을 실행으로 확인함 |
| `index.lock`은 지우지 않고 다시 시도 | 판단: 다른 세션의 git 명령이 도는 중에 잠금 파일을 지우면 저장소가 꼬일 수 있음 |
| `git stash`, 파일 없는 `checkout`·`restore`, `reset --hard`, `clean`, 브랜치 전환, 전체 포매터 금지 | 판단: 폴더 전체에 작용해 다른 세션의 커밋 안 된 작업을 지우거나 바꿈 |
| 패키지 설치와 통합 서버는 lead만, 포트는 세션마다 | Codex 0.163 소스: 세션을 끄면 그 세션이 띄운 프로세스도 끝남. 판단: 공용 `.venv`·`node_modules`를 동시에 설치하면 깨질 수 있음 |
| 담당자 질문은 ask가 모아 중복을 빼고 묶음으로 | 판단: 담당자 문답은 사람이 손으로 옮기므로 묻는 횟수와 중복을 줄여야 함 |
| 시간표: 첫 통합, 기능 동결, 작업 마감 20분 전 제출 시작 | 공식: 종료 10분 전부터 제출 시작 권장. 판단: 여유를 더 둠 |
| 요구사항에 없는 기능 금지 | 평가 도구 개발팀 인터뷰: 과잉 설계는 중점 감점 대상 |
| 실행 출력으로 검증, 실패하면 같은 검증으로 재확인 | 평가 도구 공개 자료의 충족 신호 |
