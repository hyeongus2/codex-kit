# 과제 모양 판별과 문제 재정의

lead가 쓴다. 과제를 처음 받으면 split-parts보다 먼저 한다. 키트는 화면을 보지 못한다. 작업 폴더의 파일만 읽고, 화면이나 공지로만 나온 것은 사람이 lead 창에 쳐 준 내용을 쓴다.

**[사람이 정함]** 표시가 붙은 곳은 AI가 대신 정하지 않는다. 사람에게 번호와 이유를 같이 말해 달라고 한다("2번, ○○라서"). 그 말을 DECISIONS.md '사람이 한 말'에 그대로 적고 정한 사람을 사람으로 적는다. 이유가 없으면 한 번 묻고, 그래도 없으면 'AI 추천 채택(이유 미제시)'로 적는다.

## 1. 갈래 판별
1. README, 과제 안내, 작업 폴더(데이터, 소스, docs/)에서 아래를 찾는다. 찾은 것은 출처(문장, 파일)와 함께 PLAN.md '과제 모양'에 적는다.
   - 과제 모양
   - 담당자 있음·없음과 수. README에 담당자 목록(이름, 역할, 특성)이 있으면 ask가 INTERVIEW.md '담당자 목록'에 옮긴다
   - 서술형·확인 문제
   - 과제 수와 마감, 중간 제출
   - 점심에 경기 시계가 도는지
   - 발표 자료 제출, 패키지 설치·외부 접속
2. 과제 모양은 이렇게 가린다.
   - 정해진 과제: 만들 것, 기능 요구, 제출 형식이 구체적이다.
   - 열린 문제: 상황과 데이터만 주고 문제를 정하라고 하거나, 제출물이 제안·보고서다.
   - 중간: 결과물 형태(예: 웹 화면, 예측 결과 파일)만 정해지고 무엇을 개선할지는 열려 있다. 정해진 과제로 진행하고, ask가 발굴 질문을 조금 더 하게 한다.
   - 애매하면 3의 확인 목록에 넣어 사람에게 묻는다. 담당자가 있으면 work/lead.md '질문'에 "꼭 만들어야 하는 결과물이 정해져 있나요?"를 첫 질문 후보로 적어 ask에 보낸다.
3. 파일에서 못 찾은 것만 모아 사람에게 짧은 확인 목록으로 한 번 묻는다. 사람은 개회 공지에서 들은 대로 답한다. 답을 기다리는 동안 멈추지 않고 data-profile을 시작한다.
   ```
   공지에서 들은 대로 줄마다 있음 / 없음 / 모름(또는 값)으로 답해 주세요.
   1. 과제 수와 마감 시각:
   2. 점심에 경기 시계가 도는지:
   3. 물어볼 담당자가 있는지:
   4. 서술형·확인 문제가 있는지, 언제:
   5. 중간 제출이 있는지:
   6. 발표 자료를 내는지:
   7. 패키지 설치·외부 접속이 되는지:
   ```
4. "모름"이면 틀렸을 때 손해가 적은 기본값으로 진행하고, DECISIONS.md에 '가정'으로 기본값과 함께 적는다. 공지가 나와 사람이 알려 주면 PLAN.md를 고치고 그 가정 항목 아래에 결과를 덧붙인다.
   - 점심 시계: 돈다고 보고 이른 쪽 마감으로 잡는다.
   - 서술형·확인 문제: 있다고 보고 결정 이유와 검증 숫자를 기록에 남긴다.
   - 중간 제출·발표 자료: 있다고 보고 최소판을 일찍 통합한다.
   - 과제 수: README에 보이는 과제 수로 본다.
   - 담당자: 있다고 보고 ask가 질문을 준비하게 한다(질문을 준비해 두는 손해가 묻지 못하는 손해보다 작다). 보낼 상대가 없다고 확인되면 가정 확인 블록으로 바꾼다.
   - 설치·외부 접속: 표준 라이브러리로 되는 길을 먼저 잡고, 설치는 AGENTS.md '실행 환경'대로 해 본다.
5. PLAN.md '시간표'의 두 줄(점심 시계, 과제 블록별 마감)을 채운다. 나머지 시각은 AGENTS.md '시간'대로 정한다.

## 2. 정해진 과제
- 담당자 있음: 여기서 끝낸다. 기존 흐름(data-profile, 요구사항, split-parts)으로 간다.
- 중간: 위와 같고, ask에 발굴 질문(지금 방식, 새는 시간·불량, 안 된 시도)을 몇 개 더 해 달라고 요청한다.
- 담당자 없음: 가정 확인 블록을 사람에게 보인다. **[사람이 정함]** 사람은 틀린 줄만 고친다. 받아들인 시각과 고친 줄을 PLAN.md '과제 모양'에, 가정마다 DECISIONS.md에 적은 뒤 기존 흐름으로 간다.

가정 확인 블록은 한 줄에 가정 하나다. 결과가 크게 갈리는 가정을 위에 둔다. 근거를 못 붙이면 '근거 없음'이라고 쓴다.

| # | 가정 | 기본값 | 근거 |
|---|---|---|---|
| A1 | 불량 판정은 데이터의 판정 열을 그대로 쓴다 | 판정 열 값 | README 2문단, data/lots.csv 'result' 열 |
| A2 | wafer 번호는 lot 안에서만 유일하다 | lot+wafer를 키로 씀 | wafer 번호 1~25가 lot 120개마다 반복 |

## 3. 열린 문제 (담당자 있음)
1. 발굴 질문은 ask가 interview-questions 스킬로 만든다. lead는 질문을 직접 보내지 않고, 데이터에서 본 이상한 점만 work/lead.md '질문'에 적는다. ask가 없으면 띄워 달라고 한다.
2. 그동안 lead는 data-profile로 데이터 구조를 보고 '지금 방식'의 기준선 숫자를 잰다. 어느 문제를 고르든 쓰인다. 예: 지금 규칙이 잡는 불량 수와 놓치는 수, 한 건을 처리하는 단계 수, 예산을 넘긴 건수.
3. PLAN.md '후보 문제'에 후보를 적어도 3개 적는다. 상한은 없다. 후보마다 지금 방식과 비용, 근거(담당자 답 Q번호 또는 데이터에서 센 숫자), 오늘 안에 숫자로 보일 수 있나, 현장 효과를 적는다. 근거를 못 붙이면 '근거 없음'이라고 쓰고 숫자를 지어 붙이지 않는다.
   - 후보는 해법 이름(대시보드, 챗봇)이 아니라 줄일 손실로 쓴다. 예: "검사 대기로 lot이 멈추는 시간을 줄일 수 있나".
   - 지금 방식이 당연하게 여기는 전제를 하나씩 의심해 본다: 왜 꼭 이 순서·기준·주기인가, 다르게 하면 무엇이 달라지나.
4. 가능성 시험: 후보마다 짧은 시험을 `exp/<후보>/`에서 같은 데이터·같은 지표로 돌린다. 데이터 나누기와 지표는 compare-experiments 스킬의 공통 틀로 먼저 정한다. 시험은 완성품이 아니라 '오늘 안에 숫자로 보일 수 있나'만 본다. 후보가 적으면 lead의 하위 에이전트로 동시에 돌리고, 오래 걸리면 세션 표에 실험 part를 적어 사람에게 띄워 달라고 한다. 결과는 '후보 문제'에 적는다.
5. **[사람이 정함] 풀 문제.** 후보, 근거, 시험 숫자, 현장 효과를 한 표로 보여 준다. 추천을 하나 표시해도 되지만 고르는 것은 사람이다. 고른 것과 사람이 한 말을 '후보 문제'와 DECISIONS.md에 적는다.
6. 고른 문제를 담당자에게 값으로 확인한다. work/lead.md '질문'에 숫자를 넣은 질문을 적어 ask에 보낸다. 예: "lot 하나를 재검사하는 데 30분쯤 걸리는 게 맞나요?" 답이 크게 다르면 후보 표를 다시 보여 준다.
7. **[사람이 정함] 성공 지표.** PLAN.md '비교 기록'에 지금 방식, 새 방식, 같은 데이터, 결과 보기 전에 정한 판정 기준을 적고 사람에게 지표가 맞는지 확인받는다(예: 놓친 불량 수가 먼저인가, 잘못 잡은 정상 수가 먼저인가). 성공 기준은 같은 데이터로 지금 방식과 새 방식을 비교한 숫자다.
8. 오늘 끝까지 도는 것 하나만 만든다. 큰 그림(다른 공정으로 넓히기, 실시간 연동)은 PLAN.md '결과와 한계'의 '더 하면 좋을 것'에 다음 단계로 적는다.

## 4. 열린 문제 (담당자 없음)
질문 대신 README와 데이터로 후보를 만든다. 근거는 데이터에서 센 숫자와 README 문장뿐이다. 3의 2~5와 7을 같게 하고, 6의 담당자 확인 대신 가정 확인 블록을 낸다. 블록에는 고른 문제의 지금 방식 비용, 지표, 데이터 해석의 가정을 넣는다. **[사람이 정함] 가정 받아들이기.**

## 5. 끝나면
- 고른 문제와 성공 기준을 PLAN.md '목표와 범위'(문제, 성공 기준, 만든다, 안 만든다)에 넣는다. 그다음 기존 흐름(요구사항 R번호, split-parts)으로 간다.
- 방법을 여럿 비교해야 하면 compare-experiments 스킬을 쓴다.
- 이 스킬에서 정한 것(과제 모양과 근거, 가정과 기본값, 고른 문제, 성공 지표)을 DECISIONS.md에 적는다.
- PLAN.md, DECISIONS.md, work/lead.md를 파일을 지정해 커밋한다(AGENTS.md 'git').

## 하지 않을 것
- 공지 내용을 추측해 확정으로 적기 (모르면 가정으로 적는다)
- 사람 대신 풀 문제나 성공 지표 고르기
- 근거 없는 후보에 숫자 지어 붙이기, 측정하지 않은 현장 효과를 사실처럼 적기
- 화면을 보려고 브라우저나 화면 도구 쓰기
