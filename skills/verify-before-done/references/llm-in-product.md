# 결과물 안에서 LLM을 부를 때

만드는 결과물(앱·스크립트)이 실행 중에 LLM을 부를 때만 읽는다. LLM 기능은 PLAN.md 요구사항이나 '만든다'에 있을 때만 넣는다.

- 판정·선정·계산·순위는 코드가 한다. LLM은 그 결과를 설명하는 문장만 쓴다. LLM 출력이 숫자나 판정을 바꾸지 않게 한다.
- 호출은 함수 하나(예: `call_llm`)로 모은다. 타임아웃을 두고, 실패하면 한 번만 다시 시도하고, 그래도 실패하면 규칙 기반 문장(템플릿)으로 대체한다. 화면·출력에 대체 경로를 탔는지 표시한다(예: `source: fallback`).
- temperature 0으로 부르고, 같은 입력의 응답은 캐시한다.
- JSON으로 받으면 형식과 필수 키를 검사하고, 틀리면 대체 경로로 간다.
- LLM 문장에 나온 숫자·이름(장비, lot, 사람 등)이 입력 데이터에 있는지 코드로 대조한다. 없는 것이 있으면 그 문장을 버리고 대체 문장을 쓴다.
- 테스트는 고정 응답(fixture)으로 돌린다. fixture 통과를 실제 연동 확인이라고 보고하지 않는다. 실제 호출을 해 봤으면 따로 적는다.
- 주최 측이 준 API 환경변수는 이름만 확인한다(예: `env | cut -d= -f1 | grep -i -E 'llm|openai|api'`). 값은 출력·기록·커밋하지 않는다. 개인 API 키는 쓰지 않는다. 주최 측 키가 없으면 대체 경로만으로 동작하게 둔다.

근거: 다른 해커톤 샌드박스에 주최 측 LLM 게이트웨이 환경변수가 있어, 만든 앱에서 LLM을 부를 수 있었다는 참가자 기록이 있다.
