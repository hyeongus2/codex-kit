# 완료 전 검증

## 순서
1. PLAN.md '합의된 요구사항'의 성공 기준과 이번 단계 목표를 하나씩 나열한다.
2. 각 항목을 실제로 확인한다: 테스트 실행, 스크립트 실행, 서버라면 `curl`로 응답 확인. 명령과 출력의 핵심을 보여 준다. 화면이 있는 결과물이면 사람이 Browser 미리보기에서 확인할 포트, 경로, 동작을 알려 준다.
3. 실패한 항목이 있으면 원인을 찾아 고치고 같은 명령으로 다시 확인한다. 통과할 때까지 완료라고 말하지 않는다.
4. 범위 점검: 이번 변경에 '만든다'에 없는 기능, 설정, 추상화가 들어갔는지 본다. 있으면 빼거나, 남겨야 하는 이유를 DECISIONS.md에 적는다.
5. 보안 점검: `git diff`로 바뀐 파일에 키·토큰·비밀번호 값이 들어갔는지 확인한다.
6. 기록: PLAN.md 진행에 시각과 함께 체크하고, 예상 밖 발견과 다음 할 일을 갱신한다. 이번 단계의 결정을 DECISIONS.md에 추가한다.
7. 커밋: `git status`로 바뀐 파일을 보고, 이번 단계 파일만 하나씩 `git add` 한 뒤 "무엇: 왜" 메시지로 커밋한다. push하지 않는다.
8. 보고: 확인한 것, 확인하지 못한 것, 다음 단계를 세 줄로 말한다.
