# 제출 전 점검

새 기능은 만들지 않는다. 깨진 것을 고치는 것만 한다.

## 순서
1. README와 과제 안내에서 필수 조건과 제출물(파일 이름, 경로, 형식)을 모두 뽑아 체크리스트로 만든다. 각각 실제 파일과 실행으로 확인해 표시한다.
2. PLAN.md에 적힌 실행·테스트 방법을 처음 보는 사람처럼 그대로 다시 실행해 본다. 틀린 곳은 고친다.
3. 전체 테스트와 실행을 한 번 더 돌려 결과를 보여 준다.
4. PLAN.md '결과와 한계'를 채운다: 완성한 것, 못 한 것과 이유, 남은 위험, 더 하면 좋을 것.
5. DECISIONS.md를 정리한다: 빠진 결정을 추가하고, 근거 칸이 빈 줄을 채운다.
6. 키·토큰 값이 파일이나 커밋에 남지 않았는지 확인한다.
7. 남은 변경을 파일을 지정해 커밋하고 `git status`가 깨끗한지 확인한다. push하지 않는다.
8. 아래 요약을 화면에만 출력한다(파일로 만들지 않는다).
   - 핵심 결정 3개: 무엇을, 왜, 무엇을 버렸나
   - 검증 방법: 어떤 명령과 데이터로 확인했나
   - 남은 한계와 위험
   - AI에게 맡긴 것과 사람이 직접 확인하거나 결정한 것
   - 구조: 주요 파일과 각 역할 한 줄씩
