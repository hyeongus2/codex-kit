# 통합

lead 세션이 쓴다. PLAN.md '시간표'의 첫 통합과 기능 동결 때는 꼭 하고, 부품이 끝날 때마다 한다.

## 순서
1. 모든 work 파일의 '상태', '요청', '예상 밖 발견'과 `git log --oneline`을 읽는다. PLAN.md '전체 진행표'를 갱신한다.
2. 나에게 온 요청(설치, 공용 파일, CONTRACT 변경, 서버 재시작)을 먼저 처리하고 work/lead.md '받은 요청 처리'에 적는다.
3. CONTRACT.md '실행·테스트 명령'대로 전체를 실행한다. 부품별 테스트를 모두 돌리고, 처음부터 끝까지 이어지는 경우를 실제로 돌린다. 부품 사이 연결은 CONTRACT.md 예시 값으로 확인한다.
4. check 세션이 있으면 work/check.md와 검사 결과를 내 실행 결과와 대조한다.
5. 깨진 곳이 있으면 원인 파일의 주인을 찾는다.
   - 공용 파일이면 lead가 고치고 다시 확인한다.
   - 다른 세션 파일이면 work/lead.md '요청'에 받는 세션, 실패한 명령, 출력 핵심, 기대 결과를 적는다.
   - 인터페이스가 서로 다르게 이해된 것이면 CONTRACT.md를 바로잡고 '변경 이력'에 적는다.
6. 통합한 서버가 있으면 lead가 띄우고 `curl`로 확인한 뒤, 사람에게 Browser에서 볼 포트와 경로와 확인할 동작을 알려 준다(AGENTS.md '화면과 서버').
7. PLAN.md '통합 단계'의 결과와 '전체 진행표', '다음 할 일'을 갱신한다.
8. 통과한 것을 파일을 지정해 커밋한다: 공용 파일, PLAN.md, CONTRACT.md, DECISIONS.md, work/lead.md.
9. 사람에게 알린다: 무엇이 이어졌는지, 무엇이 깨졌고 누구에게 요청했는지, 남은 시간 대비 진행.

## 기능 동결 때
- 위 순서를 한 번 더 한다.
- PLAN.md '시간표'에 동결을 표시하고, 사람에게 "각 세션에 '동결이야. 새 기능 없이 고치기·테스트·기록만 하고 다 되면 커밋해'라고 전해 달라"고 말한다.
- 남은 시간 안에 못 끝낼 부품은 빼고 결과와 한계에 적는다. 뺄지는 사람이 고른다.
