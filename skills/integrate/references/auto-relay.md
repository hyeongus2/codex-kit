# 자동 전달 (codex queue)

사람이 "자동 전달 켜"라고 했을 때만 쓴다. 켜기 전과 "자동 전달 꺼" 뒤에는 AGENTS.md '서로 맞추기'의 전달 줄만 쓴다.

## 무엇이 달라지나
- 전달 줄을 사람이 복사해 붙여 넣는 대신, 보내는 세션이 `codex queue`로 받는 세션에 같은 말을 직접 넣는다. 사람은 보내는 세션의 승인 창에서 y만 누른다.
- 받는 세션이 쉬고 있으면(Ready) 바로 그 말로 다음 차례를 시작한다. 일하는 중이면(Working) 하던 차례가 끝난 뒤 이어서 받는다. 하던 일을 끊지 않는다.
- 보내는 때와 받는 세션, 할 말은 전달 줄과 같다('서로 맞추기'의 세 경우).

## 세션 ID
- 모든 세션은 시작할 때 `echo $CODEX_THREAD_ID`를 실행해 결과를 자기 work 파일(lead는 work/lead.md) 맨 위 '세션 ID'에 적는다. 자동 전달을 켜지 않아도 적어 둔다.
- 받는 세션의 ID는 `rg -n '^- 세션 ID' work/<받는 역할>.md`로 찾는다. 세션을 새로 켜서 ID가 바뀌면 새 ID로 고친다.

## 켜기
1. 사람이 lead에 "자동 전달 켜"라고 한다.
2. lead는 CONTRACT.md '변경 이력'에 `자동 전달 켜짐(HH:MM)`을 적고 커밋한다.
3. lead는 세션 ID가 적힌 세션마다 `codex queue`로 "자동 전달 켜짐. CONTRACT.md 변경 이력 확인"을 보낸다. 이것이 첫 시험이다. 받은 세션이 움직이지 않으면 사람에게 알리고 끈다(변경 이력에 `자동 전달 꺼짐(HH:MM): 이유`).
4. 다른 세션은 단계 전후 읽기에서 변경 이력을 보고 따른다.

## 보내기
- 명령: `codex queue --thread <받는 세션 ID> --message "<전달 줄의 따옴표 안 말>"`. 말은 전달 줄과 같게, 누가 보냈는지 알 수 있게 쓴다(예: "part-api 2단계 끝(커밋 abc1234). 통합해").
- 샌드박스 안에서는 이 명령이 막히므로 처음부터 승인 요청으로 실행한다. 승인 창에서 사람은 y를 고른다. p(다시 묻지 않기)는 메시지까지 통째로 저장돼 다음 전달에 맞지 않는다.
- 그 차례의 마지막 답변 끝에는 전달 줄 대신 `전달함(queue) → lead: "…"`를 쓴다. 사람은 이 줄을 붙여 넣지 않는다.
- 실패하면(명령 오류, 승인 거절, 받는 세션 ID 없음) 지금처럼 `전달 → <받는 세션>: "…"` 줄을 쓴다. 사람이 붙여 넣는다.

## 멈추기
- 사람 말 없이 같은 상대와 연달아 세 번 주고받았으면 네 번째는 보내지 않고 전달 줄로 쓴다. 사람이 그 세션에 말을 넣으면 다시 센다.
- 사람이 "자동 전달 꺼"라고 하면 lead가 변경 이력에 `자동 전달 꺼짐(HH:MM)`을 적는다.

## 하지 않을 것
- 담당자에게 보내기, 사람의 결정·승인 대신하기, 할 일을 주지 않는 알림 보내기("대기 중", "확인했어").
