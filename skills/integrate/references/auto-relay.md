# 자동 전달 (codex queue)

사람이 "자동 전달 켜"라고 했을 때만 쓴다. 켜기 전과 "자동 전달 꺼" 뒤에는 AGENTS.md '서로 맞추기'의 전달 줄만 쓴다.

## 무엇이 달라지나
- 전달 줄을 사람이 복사해 붙여 넣는 대신, 보내는 세션이 `codex queue`로 받는 세션에 같은 말을 직접 넣는다. 사람은 보내는 세션의 승인 창에서 y만 누른다.
- 받는 세션이 쉬고 있으면(Ready) 바로 그 말로 다음 차례를 시작한다. 일하는 중이면(Working) 하던 차례가 끝난 뒤 이어서 받는다. 하던 일을 끊지 않는다.
- 보내는 때와 받는 세션, 할 말은 전달 줄과 같다('서로 맞추기'의 세 경우).

## 세션 ID
- 모든 세션은 시작할 때 `echo $CODEX_THREAD_ID`를 실행해 결과를 자기 work 파일(lead는 work/lead.md) 맨 위 '세션 ID'에 적는다. 자동 전달을 켜지 않아도 적어 둔다.
- 받는 세션의 ID는 `rg -n '^- 세션 ID' work/<받는 역할>.md`로 찾는다. 세션을 새로 켜서 ID가 바뀌면 새 ID로 고친다.

## 켜기
1. 사람이 lead에 "자동 전달 켜"라고 한다.
2. lead는 샌드박스 안에서 `readlink -f /proc/$PPID/exe`로 Codex 실행 파일의 절대 경로를 얻는다. 승인 실행에서는 `codex`가 PATH에 없을 수 있어서(11/11 시험에서 실제로 `command not found`) 모든 세션이 이 절대 경로를 쓴다.
3. lead는 CONTRACT.md '변경 이력'에 `자동 전달 켜짐(HH:MM), codex 경로: <절대 경로>`를 적고 커밋한다.
4. lead는 세션 ID가 적힌 세션마다 "자동 전달 켜짐. CONTRACT.md 변경 이력 확인"을 보낸다. 이것이 첫 시험이다. 사람은 받는 세션 탭이 스스로 움직이는지 본다. 보내기가 실패하면 사람에게 알리고 끈다(변경 이력에 `자동 전달 꺼짐(HH:MM): 이유`).
5. 다른 세션은 단계 전후 읽기에서 변경 이력을 보고 따른다.

## 보내기
- 명령: `<codex 경로> queue --thread <받는 세션 ID> --message "<전달 줄의 따옴표 안 말>"`. codex 경로는 `rg -n 'codex 경로' CONTRACT.md`로 찾는다. 말은 전달 줄과 같게, 누가 보냈는지 알 수 있게 쓴다(예: "part-api 2단계 끝(커밋 abc1234). 통합해").
- 샌드박스 안에서는 이 명령이 막히므로 처음부터 승인 요청으로 실행한다. 승인 창에서 사람은 y를 고른다. p(다시 묻지 않기)는 메시지까지 통째로 저장돼 다음 전달에 맞지 않는다.
- 보내기 전 점검: 받는 세션에 새 할 일(통합, 확인, 담당자에게 보낼 새 질문, 고칠 것)이 생겼을 때만 보낸다. 상대가 할 일이 없는 완료·갱신 알림은 보내지 않고 자기 work 파일과 CONTRACT.md에만 적는다(상대는 단계 전후 읽기에서 본다). 한 차례에 같은 상대에게는 한 번만, 여러 일은 한 메시지로 묶는다. 말은 한국어로 쓴다.
- lead에는 lead가 기다리던 일이 끝났을 때(요청한 단계 완료, 통합할 커밋)와 lead의 결정이 필요할 때만 보낸다. 받는 세션은 일하는 중에 온 말을 한 차례에 하나씩만 받으므로, 보낼 것이 더 생기면 새로 보내지 말고 자기 work 파일 '요청'에 덧붙인다(lead는 단계 전후 읽기에서 본다). 11/11 리허설에서 lead 앞에 36개가 밀려 최대 49분 늦게 도착했고, 제출 준비 뒤에도 22건을 처리했다.
- ask에는 담당자에게 보낼 질문이 새로 생겼을 때만 보낸다. ask가 queue로 쉬지 않고 일하면 사람이 담당자 답을 붙여 넣을 틈이 없다(11/11 리허설에서 담당자 답이 14분 늦게 들어감).
- 사람의 말을 옮길 때는 따옴표로 그대로 옮기고 범위를 넓히지 않는다. 예: 사람이 "생산관리팀에는 물을 수 없어"라고 했으면 그 팀에 묻지 않을 뿐, 다른 담당자에게 실제 사례를 묻는 질문은 그대로 둔다(11/11 리허설에서 "긴급 질문 반복하지 마"로 넓혀져 질문이 철회됨).
- 그 차례의 마지막 답변 끝에는 전달 줄 대신 `전달함(queue) → lead: "…"`를 쓴다. 사람은 이 줄을 붙여 넣지 않는다.
- 실패하면(명령 오류, 승인 거절, 받는 세션 ID 없음) 지금처럼 `전달 → <받는 세션>: "…"` 줄을 쓴다. 사람이 붙여 넣는다.

## 멈추기
- 보낸 쪽이 직접 센다: 사람이 자기 세션에 말을 넣은 뒤로 같은 상대에게 queue로 보낸 수가 셋이면, 네 번째부터는 전달 줄로 쓴다. 사람이 그 세션에 말을 넣으면 다시 0부터 센다. 이 제한을 풀지 사람에게 묻지 않는다.
- 사람이 "자동 전달 꺼"라고 하면 lead가 변경 이력에 `자동 전달 꺼짐(HH:MM)`을 적는다.
- lead가 final-check를 시작하면 먼저 변경 이력에 `자동 전달 꺼짐(HH:MM): 제출 준비`를 적고 커밋한다. 그 뒤로는 모든 세션이 queue를 쓰지 않고 전달 줄만 쓴다. 이미 쌓인 queue 말은 받은 세션이 '이미 반영' 한 줄로 끝낸다.

## 받았을 때
- queue로 받은 말이 이미 처리한 일이면(이미 커밋함, 이미 반영함) '받은 요청 처리'에 "이미 반영(커밋 abc1234)" 한 줄만 적고 그 차례를 바로 끝낸다. 다시 읽고 다시 점검하지 않는다. 11/11 리허설에서 lead 앞에 queue가 36개 밀려 36분 늦게 처리됐다.

## 하지 않을 것
- 받았다는 답장. 받은 세션은 '받은 요청 처리'에 적기만 하고, 그 일을 끝내 상대에게 할 일이 생겼을 때만 보낸다(전달 줄을 쓰던 때와 같다). 첫 시험 메시지에도 답장하지 않는다. 답장은 사람의 승인만 늘리고 서로 주고받기를 만든다(11/11 시험에서 실제로 생김).
- 담당자에게 보내기, 사람의 결정·승인 대신하기, 할 일을 주지 않는 알림 보내기("대기 중", "확인했어").
