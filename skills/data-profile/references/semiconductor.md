# 반도체 제조 데이터 함정

이 문서는 함정 확인용이다. 과제 범위를 늘리지 않는다. 정의가 과제 문서나 담당자 답과 다르면 그쪽을 따른다.

## 언제 읽나
열 이름에 lot, wafer, die, bin, yield, step, tool·eqp(장비), chamber, recipe, PM 같은 반도체 제조 데이터가 보일 때 data-profile 3번 점검과 함께 읽는다.

## 최소 용어
| 용어 | 뜻 | 데이터에서 |
|---|---|---|
| lot | 같이 흐르는 웨이퍼 묶음(흔히 25장). 쪼개지고 합쳐진다 | `LOT_ID`, `PARENT_LOT` |
| wafer | 원판 한 장. lot 안 순번(슬롯)과 각인 ID가 따로일 수 있다 | `WAFER_ID`, `SLOT` |
| die | 웨이퍼 위 칩 하나. 웨이퍼 안 좌표로 가리킨다 | `X`, `Y`, `DIE_ID` |
| bin | 테스트 결과 분류 번호. bin 1이 양품인 경우가 많지만 정해진 것은 아니다 | `HARD_BIN`, `SOFT_BIN` |
| 웨이퍼 테스트(EDS) | 칩마다 전기 검사. 메모리는 리페어 뒤 재테스트가 이어진다 | `TEST_STEP`, `RETEST_NO`, `REPAIR_FLAG` |
| step·tool·chamber·recipe | 공정 단계, 장비, 장비 안 처리실, 조건 묶음(버전 있음) | `STEP`, `EQP_ID`, `CHAMBER`, `RECIPE_VER` |
| PM | 예방 정비. 직후에 공정이 흔들릴 수 있다 | `PM_DATE` |
| OOC / OOS | 관리한계 이탈(조사할 신호) / 규격 밖(불합격) | `UCL`, `LCL`, `USL`, `LSL` |

## 함정과 확인
1. **수율 합치기**: 여러 웨이퍼·lot을 합친 수율은 `합친 양품 ÷ 합친 대상 다이`다. 행마다 분모가 다르면 행별 수율의 단순 평균은 틀린다. 어느 단계 수율(라인, 웨이퍼 테스트, 패키지, 누적은 곱)인지와 분모(총 다이, 미검사 포함 여부)를 먼저 정한다. 확인: `sum(good)/sum(tested)`와 `mean(good/tested)`를 같이 출력한다. 지금 방식(README·보고서 숫자)이 단순 평균으로 재현되면 그 값은 '지금 방식 기준선'으로만 쓰고 공식·비교 지표로 삼지 않는다. 두 값을 넣어 담당자에게 묻는다(예: "10월 수율이 웨이퍼 평균으로 86.7%, 전체 양품 ÷ 전체 다이로 87.2%인데 회의에 쓰는 공식은 어느 쪽인가요?"). 답이 없으면 합친 비율을 쓰고 단순 평균을 함께 적는다. README 숫자와 맞는다는 것은 지금 방식을 재현했다는 뜻이지 맞는 정의라는 뜻이 아니다.
2. **결함 수와 불량 다이 수**: 한 다이에 결함이 여럿일 수 있고, 수율에 영향 없는 결함도 많다. 확인: 결함 행 수와 결함이 있는 고유 `(lot, wafer, x, y)` 수를 나란히 센다.
3. **재검사·리페어**: 재검사가 있으면 다이 하나에 행이 여럿이다. 첫 검사 수율과 재검사 반영 최종 수율을 섞지 않는다. 회복률은 bin마다 다르다. 메모리면 리페어 전·후 중 어느 수율인지 정한다. 확인: `(lot, wafer, x, y)`당 행 수가 2 이상인 다이 수, bin별로 첫 실패 뒤 재검사 통과 수.
4. **조인 행 불어남**: 표마다 한 행의 단위(lot, 웨이퍼, 다이, 측정점, 단계, 검사 차수)가 다르다. 웨이퍼 번호는 lot 안에서만 유일할 수 있어 `lot+wafer`를 함께 키로 쓴다. 확인: 키 후보의 중복 수가 0인지, 조인 전후 행 수와 분자·분모가 그대로인지.
5. **좌표 정렬**: 결함 검사 장비와 테스터의 좌표 원점·방향(노치)·다이 크기가 다를 수 있다. 맞추기 전에는 결함 맵과 bin 맵을 겹치지 않는다. 확인: 두 표의 x·y 최소·최대와 서로 겹치는 좌표 비율.
6. **lot 쪼개기·합치기(genealogy)**: lot ID가 중간에 바뀌거나 나뉘고, 한 흐름에서 같은 장비를 여러 번 지난다. 확인: 부모 lot 열이 있는지, 단계별 lot ID 종류 수, `(lot, step)`당 행이 여럿인지.
7. **관리도(SPC)**: OOC도 OOS도 원인 확정이 아니다. 한계는 안정된 기준 기간으로 만들고 감시 기간에는 고정한다. 확인: 한계를 만든 기간과 켠 규칙을 출력에 적는다.
8. **측정점 중첩·자기상관**: 웨이퍼 안 여러 점, 웨이퍼 사이, lot 사이 변동이 겹친다. 측정점마다 관리도를 그리거나 앞뒤가 이어진 센서 값에 I-MR을 그대로 쓰면 오경보가 많다. 확인: 웨이퍼당 측정점 수, 웨이퍼 평균의 1차 자기상관.
9. **Cpk**: 규격(USL·LSL)이 있고, 관리 상태이고, 대략 정규분포일 때만 계산한다. 치우친 값(파티클 수 등)에는 그대로 쓰지 않는다. 확인: 규격 열 유무, 왜도, 쓴 σ(군내 `MR̄/1.128`이면 Cpk, 전체 표준편차면 Ppk).
10. **상관과 원인**: 불량 lot이 같이 지나간 장비 찾기는 후보 좁히기다. lot이 늘 같은 장비 조합으로 흐르면 장비 효과와 시기 효과를 나눌 수 없고, 원인이 장비 조합이면 하나씩 보는 비교는 놓친다. 확인: 장비×기간 교차표의 빈 칸 수.
11. **장비·계측기·테스터의 기간 이상**: 원인 후보와 별개로 계측기·테스터·새 장비마다 기간을 나눠 본다. 특정 기간의 bin 급증, 계측값 계단 변화, 새 장비 투입 시점은 담당자만 아는 사정(교정, 고장, 자격)의 흔적이다. 확인: 계측기·테스터별 날짜 단위 평균과 bin 비율. 튀는 구간은 대상과 기간을 넣어 work 파일 '질문'에 적는다(예: "TESTER-04에서 10/14~16에 bin 3이 다른 날의 3배인데 그때 무슨 일이 있었나요?").
11. **다중 비교**: 단계·장비·규칙을 많이 볼수록 우연히 걸리는 것이 는다. 3σ 규칙 하나면 평균 371점마다, Western Electric 규칙을 다 켜면 약 92점마다 오경보가 난다(NIST). 확인: 비교한 수를 적고, 라벨을 섞은 데이터에서도 같은 1위가 나오는지 본다.
12. **PM 직후**: 정비·세정 직후 상태가 바뀐다(시즈닝, 첫 웨이퍼 효과). 확인: 추세에 PM 시점을 표시하고, PM 뒤 첫 몇 장과 더미·모니터 웨이퍼를 따로 센다.
13. **누수**: 같은 lot의 웨이퍼는 조건이 비슷해서 학습·검증을 lot 단위로, 운영을 흉내 내려면 시간 순서로 나눈다. 결측 대치·특성 선택·정규화는 학습 구간에서만 맞추고, 예측 시점 뒤에 생기는 값은 입력에서 뺀다. 확인: 학습·검증 lot 교집합이 0건인지, 검증 최소 시각이 학습 최대 시각보다 뒤인지.
14. **불균형**: 불량이 드물면 '전부 정상'도 정확도가 높다. 예: UCI SECOM은 1,567건 중 불량 104건이라 전부 정상이라고 해도 93.4%다. 확인: 다수 클래스만 찍은 기준 정확도를 먼저 출력하고, 불량 재현율·놓친 불량 수·정밀도·PR-AUC를 보고한다.
15. **덮어쓴 기록**: 재측정·재작업·특채로 값이나 판정이 바뀌고, 판정 기준에도 버전이 있다. 최종값만 있는 표로는 첫 측정 분포를 말하지 않는다. 확인: `(wafer, step)`당 측정 행 수, 판정 기준 버전·적용 기간 열 유무.
16. **웨이퍼맵 패턴**: 공간 모양(가운데, 가장자리 고리, 긁힘 등)과 원인을 잇는 표는 자료마다 다르다. 원인 후보를 여러 개 적고, 장비 이력·공정 데이터로 확인한다.

## 보고 문장 꼴
- 신호: "[후보] (단계·장비·챔버)에서 (기간) (지표)가 (숫자, 비교 대상 대비). 원인은 담당자·장비 이력 확인 필요."
- 원인, 불량 확정, 장비 탓은 담당자 답이나 이력 데이터가 근거로 있을 때만 쓴다. 없으면 INTERVIEW.md '물어볼 질문'에 근거 숫자와 함께 넣는다.
- 결과에 쓴 정의(수율 단계와 분모, 재검사 처리, 한계를 만든 기간, 켠 규칙, σ 종류)를 함께 적는다.
