# 반도체 제조 데이터 함정

이 문서는 함정 확인용이다. 과제 범위를 늘리지 않는다. 정의가 과제 문서나 담당자 답과 다르면 그쪽을 따른다.

## 언제 읽나
열 이름에 lot, wafer, die, bin, yield, step, tool·eqp(장비), chamber, recipe, PM 같은 반도체 제조 데이터가 보일 때 data-profile 3번 점검과 함께 읽는다.

## 최소 용어
| 용어 | 뜻 | 데이터에서 |
|---|---|---|
| lot | 같이 흐르는 웨이퍼 묶음(용기 하나가 보통 25장이지만 분할·폐기로 더 적을 수 있다). 쪼개지고 합쳐진다 | `LOT_ID`, `PARENT_LOT` |
| wafer | 원판 한 장. lot 안 순번(슬롯)과 각인 ID가 따로일 수 있다 | `WAFER_ID`, `SLOT` |
| die | 웨이퍼 위 칩 하나. 웨이퍼 안 좌표로 가리킨다 | `X`, `Y`, `DIE_ID` |
| bin | 테스트 결과 분류 번호. hard bin은 장비가 쓰는 큰 분류, soft bin은 세부 원인이다. 양품 bin이 여러 개(등급별)일 수 있고 bin 1=양품은 관례일 뿐이라 bin 표나 판정 열로 확인한다 | `HARD_BIN`, `SOFT_BIN` |
| 웨이퍼 테스트 | 칩마다 전기 검사(삼성은 EDS, SK하이닉스는 웨이퍼 테스트라고 부른다). 소자 특성·번인·온도별 테스트·리페어 뒤 테스트처럼 단계가 여럿이라 다이 하나에 단계별 행이 생긴다 | `TEST_STEP`, `TEST_TEMP`, `INSERTION`, `RETEST_NO`, `REPAIR_FLAG` |
| step·tool·chamber·recipe | 공정 단계, 장비, 장비 안 처리실, 조건 묶음(버전 있음) | `STEP`, `EQP_ID`, `CHAMBER`, `RECIPE_VER` |
| PM | 예방 정비. 직후에 공정이 흔들릴 수 있다 | `PM_DATE` |
| OOC / OOS | 관리한계 밖 점이나 런 규칙 위반(조사할 신호) / 규격 밖(멈추고 처리를 정할 대상. 폐기 확정은 아님) | `UCL`, `LCL`, `USL`, `LSL` |

## 함정과 확인
1. **수율 합치기**: 여러 웨이퍼·lot을 합친 수율은 `합친 양품 ÷ 합친 대상 다이`다. 행마다 분모가 다르면 행별 수율의 단순 평균은 틀린다. 어느 단계 수율(라인은 웨이퍼 수 기준, 웨이퍼 테스트, 패키지, 누적은 각 단계 수율의 곱)인지와 분모(총 다이, 미검사 포함 여부)를 먼저 정한다. '넷다이'·'그로스 다이'는 자료마다 뜻이 다르다(SK하이닉스 글은 넷다이를 양·불 합친 웨이퍼당 다이 수로 쓰고, 영어 자료의 net die는 양품 다이다). 분모로 쓰기 전에 정의를 묻는다. 확인: `sum(good)/sum(tested)`와 `mean(good/tested)`를 같이 출력한다. 지금 방식(README·보고서 숫자)이 단순 평균으로 재현되면 그 값은 '지금 방식 기준선'으로만 쓰고 공식·비교 지표로 삼지 않는다. 두 값을 넣은 질문을 우선순위 상으로 ask에 보낸다(예: "이번 달 수율이 웨이퍼 평균으로 91.3%, 전체 양품 ÷ 전체 다이로 90.8%인데 회의에 쓰는 공식은 어느 쪽인가요?"). 어느 후보 문제를 고르든 결과 숫자가 이 정의를 쓰므로 문제 선택과 상관없이 묻는다. README·과제 설명·보고서에 적힌 계산 방식("웨이퍼마다 수율을 구해 평균한 값")은 지금 방식의 설명이지 담당자가 확인한 정의가 아니다(README가 제출 지표의 계산식으로 못 박은 경우만 따른다). '담당자 정의'라고 쓰려면 이 두 값 질문에 대한 문답 Q번호를 단다. Q번호가 없으면 공식·비교 지표는 합친 비율로 하고 단순 평균을 함께 적는다. README 숫자와 맞는다는 것은 지금 방식을 재현했다는 뜻이지 맞는 정의라는 뜻이 아니다.
2. **결함 수와 불량 다이 수**: 한 다이에 결함이 여럿일 수 있고, 모든 결함이 불량을 만들지는 않는다. 결함이 있는 다이의 불량률을 그대로 결함 탓으로 돌리지 않고 결함 없는 다이의 수율과 비교한다(kill ratio). 확인: 결함 행 수와 결함이 있는 고유 `(lot, wafer, x, y)` 수를 나란히 센다.
3. **재검사·리페어·테스트 단계**: 다이 하나에 행이 여럿인 이유는 재검사만이 아니다. 테스트 단계, 온도(Hot/Cold), 리페어 전후마다 행이 생긴다. 첫 검사 수율과 재검사 반영 최종 수율을 섞지 않는다. 회복률은 bin마다 다르다. 메모리면 리페어 전·후 중 어느 수율인지 정한다. 확인: `(lot, wafer, x, y)`당 행 수를 테스트 단계·온도·리페어 전후 열로 먼저 나눈다. 같은 단계 안에서도 2 이상인 다이를 재검사로 세고, 실패 bin별로 첫 실패 뒤 재검사 통과 수를 센다.
4. **조인 행 불어남**: 표마다 한 행의 단위(lot, 웨이퍼, 다이, 측정점, 단계, 검사 차수)가 다르다. 웨이퍼 번호는 lot 안에서만 유일할 수 있어 `lot+wafer`를 함께 키로 쓴다. 확인: 키 후보의 중복 수가 0인지, 조인 전후 행 수와 분자·분모가 그대로인지.
5. **좌표 정렬**: 결함 검사 장비와 테스터는 좌표 단위(µm 대 다이 번호), 원점, 축의 +방향, 노치 방향이 다를 수 있다. 맞추기 전에는 결함 맵과 bin 맵을 겹치지 않는다. 확인: 두 표의 x·y 최소·최대와 서로 겹치는 좌표 비율.
6. **lot 쪼개기·합치기(genealogy)**: lot ID가 중간에 바뀌거나 나뉘고, 한 흐름에서 같은 장비를 여러 번 지난다. 확인: 부모 lot 열이 있는지, 단계별 lot ID 종류 수, `(lot, step)`당 행이 여럿인지.
7. **관리도(SPC)**: OOC도 OOS도 원인 확정이 아니다. 한계는 안정된 기준 기간으로 만들고 감시 기간에는 고정한다. 의도한 공정 변경(레시피·장비 교체) 뒤에는 기준 기간을 다시 잡고 그 시점을 적는다. 확인: 한계를 만든 기간과 켠 규칙을 출력에 적는다.
8. **측정점 중첩·자기상관**: 웨이퍼 안 여러 점, 웨이퍼 사이, lot 사이 변동이 겹친다. 웨이퍼 안 측정점을 부분군으로 X̄ 관리도를 그리면 한계가 웨이퍼 안 변동만 반영해 너무 좁아져 오경보가 많다. 웨이퍼 평균의 I-MR과 웨이퍼 안 산포 차트를 따로 둔다. 앞뒤 값이 양의 자기상관이면 I-MR 한계도 좁아져 오경보가 는다. 확인: 웨이퍼당 측정점 수, 웨이퍼 평균의 1차 자기상관.
9. **Cpk**: 규격이 있고(한쪽 규격이면 Cpu나 Cpl), 관리 상태이고, 대략 정규분포일 때만 계산한다. 치우친 값(파티클 수 등)에는 그대로 쓰지 않는다. 확인: 규격 열 유무, 왜도, 쓴 σ(군내 σ면 Cpk — 낱개 값이면 `MR̄/1.128`, 부분군이면 `R̄/d2` 등 / 전체 표준편차면 Ppk. 이 이름 구분은 Minitab·AIAG 관례다). 자기상관이 있으면 MR̄로 낸 σ가 작아 Cpk가 부푼다.
10. **상관과 원인**: 불량 lot이 같이 지나간 장비 찾기는 후보 좁히기다. lot이 늘 같은 장비 조합으로 흐르면 장비 효과와 시기 효과를 나눌 수 없고, 원인이 장비 조합이면 하나씩 보는 비교는 놓친다. 확인: 장비×기간 교차표의 빈 칸 수.
11. **장비·계측기·테스터의 기간 이상**: 원인 후보와 별개로 계측기·테스터·새 장비마다 기간을 나눠 본다. 특정 기간의 bin 급증, 계측값 계단 변화, 새 장비 투입 시점은 담당자만 아는 사정(교정, 고장, 자격)의 흔적일 수 있다. 확인: 계측기·테스터별 날짜 단위 평균과 bin 비율. 튀는 구간은 대상과 기간을 넣어 work 파일 '질문'에 적는다(예: "테스터 T2에서 사흘 동안 특정 불량 bin이 다른 날의 3배인데 그때 무슨 일이 있었나요?").
12. **다중 비교**: 단계·장비·규칙을 많이 볼수록 우연히 걸리는 것이 는다. 3σ 규칙 하나면 평균 371점마다, WECO 구역 규칙 4개를 양쪽에 켜면 약 92점마다 오경보가 난다(NIST. 정규·독립이고 한계가 정확할 때). 추세 규칙까지 켜면 더 잦다. 확인: 비교한 수를 적고, 라벨을 섞은 데이터에서도 같은 1위가 나오는지 본다.
13. **PM 직후**: 정비·세정 직후 챔버 상태가 바뀌어 첫 몇 장의 결과가 다르다(첫 웨이퍼 효과). 그래서 더미 웨이퍼로 시즈닝(챔버 길들이기)을 한다. 확인: 추세에 PM 시점을 표시하고, PM 뒤 첫 몇 장과 시즈닝·더미·모니터 웨이퍼를 따로 센다. 더미를 더 넣는 제안은 뒤 생산 웨이퍼의 'PM 뒤 몇 번째'를 그만큼 밀므로, 효과를 시간 창만이 아니라 PM 뒤 순번(장수) 기준으로도 계산한다.
14. **누수**: 같은 lot의 웨이퍼는 조건이 비슷해서 학습·검증을 lot 단위로, 운영을 흉내 내려면 시간 순서로 나눈다. 결측 대치·특성 선택·정규화는 학습 구간에서만 맞추고, 예측 시점 뒤에 생기는 값은 입력에서 뺀다. 확인: 학습·검증 lot 교집합이 0건인지, 검증 최소 시각이 학습 최대 시각보다 뒤인지.
15. **불균형**: 불량이 드물면 '전부 정상'도 정확도가 높다. 예: UCI SECOM은 1,567건 중 불량 104건이라 전부 정상이라고 해도 93.4%다. SECOM 라벨은 -1이 양품, 1이 불량이다. 공개 데이터는 라벨 부호와 값의 뜻을 문서로 먼저 확인한다. 확인: 다수 클래스만 찍은 기준 정확도를 먼저 출력하고, 불량 재현율·놓친 불량 수·정밀도·PR-AUC를 보고한다.
16. **덮어쓴 기록**: 재측정·재작업·특채로 값이나 판정이 바뀌고, 판정 기준에도 버전이 있다. 최종값만 있는 표로는 첫 측정 분포를 말하지 않는다. 확인: `(wafer, step)`당 측정 행 수, 판정 기준 버전·적용 기간 열 유무.
17. **웨이퍼맵 패턴**: 공간 모양(가운데, 가장자리 고리, 긁힘 등)과 원인을 잇는 표는 자료마다 다르다. 원인 후보를 여러 개 적고, 장비 이력·공정 데이터로 확인한다. 가장자리에 걸친 다이를 분모에 넣었는지도 본다.
18. **파라메트릭 테스트와 다이 테스트**: WAT·PCM·EPM은 스크라이브 라인 테스트 패턴을 웨이퍼당 몇 곳만 잰 값이라 특정 다이의 값이 아니다. 계측도 lot마다 일부 웨이퍼·일부 점만 잴 수 있다. 확인: 웨이퍼당 측정 위치 수, 다이 표에 붙일 때 웨이퍼 단위로 요약했는지, 잰 웨이퍼가 무작위로 골라졌는지.
19. **제품 섞임·시각 기준**: 제품마다 다이 수와 기준 수율이 달라 합친 추세나 장비 비교는 제품 구성만으로 움직인다. 장비·기간 분석은 테스트 날짜가 아니라 그 단계를 지난 시각으로 맞춘다(공정에서 테스트까지 며칠~몇 주). 확인: 기간별 제품 구성 비율, 제품별로 나눈 비교, 단계 통과 시각과 테스트 시각의 차이.

## 보고 문장 꼴
- 신호: "[후보] (단계·장비·챔버)에서 (기간) (지표)가 (숫자, 비교 대상 대비). 원인은 담당자·장비 이력 확인 필요."
- 원인, 불량 확정, 장비 탓은 담당자 답이나 이력 데이터가 근거로 있을 때만 쓴다. 없으면 INTERVIEW.md '물어볼 질문'에 근거 숫자와 함께 넣는다.
- 결과에 쓴 정의(수율 단계와 분모, 재검사 처리, 한계를 만든 기간, 켠 규칙, σ 종류)를 함께 적는다.
