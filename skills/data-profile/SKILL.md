# 데이터 점검

## 순서
1. 형식 확인: 파일 종류, 인코딩, 구분자, 시트·테이블 이름, 행·열 수. 큰 파일은 앞부분만 보고, 전체를 한 번에 출력하지 않는다.
2. 점검 코드 작성: 형식에 맞는 짧은 스크립트를 파일로 만든다. 가능하면 표준 라이브러리(csv, json, sqlite3, zipfile)만 쓴다. 다시 실행할 수 있게 남긴다.
3. 열마다 숫자로 보고한다.
   - 빈 값 수와 비율
   - 자료형 섞임 (숫자 열에 문자, 날짜 형식 여러 가지)
   - 중복 행, 키 중복
   - 숫자 열: 최소·최대, 0과 음수 개수
   - 날짜 열: 범위, 빠진 기간
   - 범주 열: 값 목록과 개수 (표기가 흔들리는 값 포함)
4. 이상한 점마다 처리 후보를 둘 이상 적고, 담당자 확인이 필요한 것을 표시한다. 그 항목은 interview-questions 스킬의 근거로 쓴다.
5. 처리를 실제로 적용하면 전후 숫자를 남긴다: 행 수, 합계·평균 같은 핵심 값이 어떻게 바뀌었는지. DECISIONS.md에 결정, 이유, 버린 대안과 함께 적는다.

## 하지 않을 것
- 담당자 확인 없이 행 삭제나 값 채우기를 확정하기
- 원본 데이터 파일 덮어쓰기 (처리 결과는 새 파일로 저장)
