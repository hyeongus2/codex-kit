# 부품 나누기

lead 세션이 쓴다. 목표는 세션 여러 개가 서로 기다리지 않고 동시에 일할 수 있게 하는 것이다.

## 입력
- 과제 README와 과제 안내, 데이터와 PLAN.md '데이터'
- PLAN.md '요구사항', INTERVIEW.md '확정된 사실'
- PLAN.md '환경'(메모리, CPU)과 '시간표'

## 순서
1. 결과물을 부품으로 나눈다. README가 정한 폴더·파일 구조를 따른다.
   - 부품끼리 고치는 파일이 겹치지 않게 나눈다. 같은 파일을 두 부품이 고쳐야 하면 파일을 나누거나 한 부품에 몰아준다.
   - 부품 사이에 오가는 것(데이터 형식, 함수, API)이 작고 분명하게 나눈다.
   - 부품마다 혼자 테스트할 수 있게 나눈다.
2. 세션을 정한다.
   - 부품 하나에 part 세션 하나를 둔다. 작은 부품은 합치거나, 다른 세션의 하위 에이전트에게 맡긴다.
   - part 이름은 맡은 기능을 나타내는 짧은 영어 단어로 짓는다(예: part-search). 번호나 글자로 짓지 않는다. 세션 표 '맡은 범위'에 한국어 한 줄 설명을 붙인다.
   - 세션 표에는 사람이 띄울 세션만 적는다. 하위 에이전트에게 맡길 작은 부품은 '부품 나누기'에 맡을 세션과 함께 적는다.
   - 독립 검사가 필요한 결과(숫자 계산, 규칙 판정, 출력 형식)가 있으면 check를 둔다.
   - 담당자 문답이 계속 필요하면 ask를 둔다.
   - 세션 수는 동시에 돌려 시간이 줄어드는 만큼 둔다. PLAN.md '환경'의 메모리와 CPU를 함께 본다.
3. CONTRACT.md를 쓴다.
   - 파일 주인: 파일 단위로 주인 세션 하나. 공용 파일은 lead. INTERVIEW.md는 ask(세션 표에 ask가 없을 때만 lead).
   - 데이터 형식과 인터페이스: 부품 사이에 오가는 것마다 형식과 실제 데이터에서 자른 예시 값.
   - 실행·테스트 명령: 모든 세션이 글자 그대로 쓸 명령을 정한다. 전체 테스트 명령 하나와 부품별 테스트 명령이다. 테스트 파일이 늘어도 명령이 바뀌지 않게 폴더 단위로 찾는 명령으로 정한다. 서버가 필요한 테스트는 스크립트가 서버를 띄우고 끄는 것까지 하게 한다. 명령에 `*`, `?`, `>`, `$(…)`, `이름=값`을 넣지 않는다. Codex는 이런 명령에 사람이 승인 창에서 허용해 둔 규칙을 적용하지 않아 매번 묻는다. 부품별 테스트는 파일 이름 패턴 대신 부품별 폴더나 파일로 나눈다.
   - 세션별 포트, 설치한 패키지.
   - 변경 이력 C1에 '처음 작성'을 적는다.
4. 뼈대를 만든다: 공용 파일, 진입점, 인터페이스 자리(예시 값을 그대로 돌려주는 가짜 구현)를 만들어 실행되는 것을 확인한다. 필요한 패키지를 설치하고 CONTRACT.md에 적는다.
5. PLAN.md를 쓴다: '세션 표'(세션, 맡은 범위, 첫 메시지, 시작 조건), '부품 나누기', '시간표', '통합 단계'. 첫 메시지에는 역할과 읽을 파일만 쓰고(예: `역할: part-search. README와 CONTRACT.md 읽고 시작해`), 그 세션에 줄 지시는 CONTRACT.md와 '부품 나누기'에 둔다.
6. 이렇게 나눈 이유와 버린 나누기 방식을 DECISIONS.md에 적는다.
7. 뼈대, PLAN.md, CONTRACT.md, DECISIONS.md, work/lead.md를 파일을 지정해 커밋한다(AGENTS.md 'git').
8. 사람에게 보여 준다: 세션 표, 부품마다 맡은 파일, 각 세션 터미널에 붙여 넣을 첫 메시지. 첫 메시지는 PLAN.md 세션 표의 문구를 글자 그대로 보여 준다. 지금 띄울 세션을 띄워 달라고 요청한다. 세션 표의 일을 하위 에이전트로 대신하지 않는다(AGENTS.md '세션과 역할'). 사람이 바꾸면 고치고 DECISIONS.md에 '정한 사람: 사람'으로 적는다.

## 나눈 뒤에
- 요구사항이 바뀌거나 세션이 막히면 나누기를 다시 본다. 파일 주인이나 인터페이스를 바꾸면 CONTRACT.md '변경 이력'에 영향받는 세션과 함께 적는다.
- 끝난 세션이 생기면 남은 일을 다시 나눠 그 세션에 맡길지 본다.
- 최소판을 통합한 뒤 남은 요구사항(후순위 포함)이 있으면 다음 부품으로 나눈다. 끝난 세션에 맡기거나 새 세션을 띄워 달라고 요청하고, 세션 표와 CONTRACT.md에 적는다.
