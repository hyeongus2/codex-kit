# 실험 비교

lead 또는 실험 part(part-<이름>)가 쓴다. **[사람이 정함]** 표시는 reframe 스킬과 같다: AI가 대신 정하지 않고, 사람이 번호와 이유를 말하면 DECISIONS.md '사람이 한 말'에 그대로 적는다.

## 1. 공통 틀 먼저
돌리기 전에 아래를 한 장으로 정한다. 갈래 사이 비교는 lead가 PLAN.md '비교 기록'에 적고, 갈래 세션이 맞춰야 할 것(나눈 데이터 파일, 결과 파일 형식, 실행 명령)은 CONTRACT.md에 넣는다. part가 이 스킬을 불렀는데 틀이 없으면 자기 work 파일에 초안을 쓰고 '요청'으로 lead에 보낸다. 자기 갈래 안의 변형만 비교하면 work 파일 '단계 계획'에 같은 칸으로 적는다.
- 지금 방식(기준선): 현장이 지금 하는 방식, 없으면 가장 단순한 방법(규칙, 평균값, 가장 많은 범주). 모든 후보를 이것과 같은 표에 둔다.
- 데이터 나누기: 평가 데이터의 정보가 학습에 새지 않게 나눈다. 시간 순서가 있으면 과거로 만들고 미래로 평가한다. 같은 lot·wafer·설비처럼 한 묶음인 행은 학습과 평가에 갈라 넣지 않는다. 반도체 데이터면 data-profile 스킬의 `references/semiconductor.md`를 본다. 나눈 결과(키 목록이나 행 번호)를 파일로 고정해 모든 갈래가 같은 파일을 읽는다.
- 지표: 현장 숫자로 정한다(놓친 불량 수, 잘못 잡은 정상 수, 예산 초과 건수, 처리 시간). 불량이 드물면 정확도 대신 재현율과 놓친 수를 본다. 서로 부딪치는 지표는 하나로 합치지 않고 둘 다 표에 둔다. **[사람이 정함]** 어느 지표가 먼저인지.
- seed: 여러 개(3~5개). 평균과 최소·최대를 같이 적는다.
- 결과 파일 형식: 갈래마다 `exp/<이름>/results.csv`, 한 줄에 실행 하나. 열은 갈래, 변형, seed, 지표들, 해 상태, 실행 초, 실행 명령으로 모든 갈래가 같게 한다.
- 결과를 보기 전에 정한 판정 기준: 예: "놓친 불량이 기준선보다 적고, 잘못 잡은 정상이 기준선의 2배를 넘지 않으면 채택 후보". 결과를 본 뒤 바꾸지 않는다. 바꿔야 하면 새 줄에 이유와 함께 적는다.

## 2. 후보 방법
세션이 문제 모양에 맞는 후보를 고른다. 아래는 예시이고 여기에 묶이지 않는다.
- 배정·편성·일정: 규칙, 그리디와 국소 개선, 정확해 솔버(정수계획 등), 그리디 해를 시작점으로 넣고 시간 상한을 건 정확해
- 예측: 단순 기준 모델, 선형·로지스틱, 트리 계열(랜덤포레스트, 부스팅)
- 이상 찾기: 관리 한계 같은 규칙, 통계 기준, 이상 탐지 모델
- 맞바꿈: 같은 방법에 가중치만 바꿔 가며(9:1 ~ 1:9)

후보 목록과 고른 이유(문제 모양, 데이터 크기, 설치 가능 여부, 설명하기 쉬운지)를 보여 주고 답을 기다리지 않고 바로 시작한다. 사람이 빼거나 더하면 따르고 그 말을 DECISIONS.md에 적는다.

## 3. 나눠 돌리기
- 갈래(방법 종류)마다 `exp/<이름>/` 폴더 주인 세션 하나를 둔다. lead가 CONTRACT.md '파일 주인'에 폴더 단위로 적는다. 갈래 수는 lead가 갈래 수, PLAN.md '환경'의 메모리·CPU, 승인 창 부담을 보고 정한다. 폴더 이름은 짧은 영어 단어로 짓는다(예: `exp/greedy/`, `exp/solver/`).
- 한 갈래 안의 변형(가중치, 하이퍼파라미터 몇 개, seed)은 하위 에이전트로 나눠 동시에 돌린다. 하위 에이전트에게 공통 틀, 맡긴 변형, 쓸 파일을 알려 주고 둘이 같은 파일을 쓰지 않게 한다. "지시하지 않은 것을 정해야 하면 코드에 `결정:` 주석을 달아라"를 붙인다. 끝나면 `rg -n "결정:" exp/<이름>`으로 모아 DECISIONS.md에 정한 사람 'AI가 정함(하위 에이전트 결정: 주석)'으로 옮긴다.
- 오래 걸리는 실행은 백그라운드로 돌리고 로그를 `exp/<이름>/` 안에 남긴다. 끝났는지는 로그 마지막 줄과 결과 파일로 확인한다. 기다리는 동안 다른 변형이나 기록을 한다.
- `exp/비교표.md`는 각 폴더의 `results.csv`를 모으는 스크립트가 만든다. 스크립트와 비교표의 주인은 한 세션(보통 lead)이고 CONTRACT.md에 적는다. 표의 숫자를 손으로 옮기지 않는다.

## 4. 최적화 결과
- 해 상태를 나눠 적는다: 최적 입증 / 가능한 해 / 시간 초과·모름 / 불가능 증명.
- 규칙·그리디 같은 휴리스틱 결과를 '최적'이라 하지 않는다. 시간 초과를 '불가능'이라 하지 않는다.
- 완전탐색이 금방 끝나는 작은 입력을 만들어 각 방법의 결과와 대조한다.
- 정확해 솔버를 돌렸으면 솔버가 낸 한계값과의 갭(%)을 적는다.
- 제약 위반 수는 결과 파일만 읽는 검사로 센다. check의 검사기가 있으면 그것을 쓴다.

## 5. 고르기
- 세션은 '최고'를 정하지 않는다. 비교표와 맞바꿈을 보여 준다. 예: "9:1이면 예산 초과 0건·불만 12%, 7:3이면 2건·5%". 모든 지표에서 다른 후보보다 나쁜 후보는 따로 표시한다.
- 숫자 하나로 승자가 갈리는 비교(같은 지표에서 seed 범위가 겹치지 않음)는 추천을 표시해도 된다. 마지막 선택은 사람이다.
- **[사람이 정함]** 사람은 표를 보여 준 세션에 고른 것과 이유를 한 번 말한다. 그 세션이 DECISIONS.md에 적는다(정한 사람: 사람, 사람이 한 말 그대로). 사람이 담당자 생각을 듣고 싶어 하면 맞바꿈 숫자를 넣은 질문을 자기 work 파일 '질문'에 적어 ask에 보낸다.
- lead가 아니면 자기 work 파일 '요청'에 `- [열림] HH:MM → lead: E1 7:3 확정, 반영해 줘(D-part-<이름>-번호)`를 적는다. lead는 PLAN.md '요구사항'·'비교 기록'과 CONTRACT.md에 반영한다. 다른 세션은 CONTRACT.md '변경 이력'으로 안다.

## 6. 결과 알리기
- 결과가 나오면 자기 work 파일 '상태'에 "결과 나옴, exp/<이름>/results.csv"를 적는다.
- 결정이 필요하면 '요청'에 → lead로 적고 답변 끝에 전달 줄을 쓴다(AGENTS.md '서로 맞추기').
- 버린 시도와 나빠진 지표도 PLAN.md '비교 기록'의 '버린 시도'에 남긴다(lead가 아니면 work 파일에 적고 lead가 옮긴다).

## 7. 입장끼리 부딪칠 때
INTERVIEW.md '입장 표'에서 부딪치는 것(예: 예산 담당은 초과 0건, 이용자 쪽은 불만 최소)이 ask의 '답 배포'나 요청(`[엇갈림]`)으로 오면, lead는 둘을 PLAN.md 요구사항과 CONTRACT.md에 지표 둘로 넣고 실험 part에 맞바꿈 실험(가중치 9:1 ~ 1:9)으로 맡긴다. 결과는 5대로 사람이 고른다.

## 8. 주장하는 범위
- 확인 수준을 나눠 말한다: 동작 확인 / 주어진 자료 안의 효과 / 실제 현장 효과. 주어진 데이터에서 놓친 불량이 30건에서 12건이 됐으면 '주어진 자료 안의 효과'다. 측정하지 않은 수율·비용 개선은 주장하지 않는다.
- 두 가지를 같이 바꾼 비교에서 한쪽을 원인이라고 하지 않는다. 하나를 고정하고 다시 비교한다.

## 하지 않을 것
- 결과를 본 뒤 판정 기준이나 데이터 나누기 바꾸기 (바꾸면 새 줄에 이유)
- 가중치·하이퍼파라미터를 평가 데이터로 고르고 그 숫자를 그대로 보고하기 (고르는 데이터와 보고하는 데이터를 나눈다)
- seed 하나의 결과로 승자 정하기
- 사람 대신 맞바꿈 고르기
